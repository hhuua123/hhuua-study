为什么值得学 Rust？

⚡ 快得离谱

编译成机器码，性能逼近 C/C++。Python 是解释器在后面追着跑，Rust 是 CPU 直接跑。

🛡 内存零事故

不靠垃圾回收器，靠「所有权」规则在编译期就把内存问题掐死在摇篮里。江湖传言：编译通过，基本就没有内存 bug。

🧵 多线程福星

数据竞争？编译器直接拒绝你。Python 的 GIL 在这里根本不存在。

🌍 硬核玩家都在用

Firefox、Linux 内核、微软、亚马逊、Discord……最吃性能的地方都有它的身影。

一句话总结：Python 教你把事做成，Rust 教你把事做得又对又快。先 Python 后 Rust，是目前最顺的升级路线之一。

第 1 章 · 徽章待领：📦 封条管理员

变量：默认贴了封条的盒子

先报个好消息：let 这语法你扫一眼就懂。再报个坏消息：它背后藏着一条 Python 里完全没有的规矩——默认不许改。

一样的开始，不一样的下场

两边都在创建变量、然后改它。Python 潇洒通过，Rust 当场翻脸：

🐍 Python
name = "Ferris"
name = "小蟹"    # 随手覆盖，没人管你
print(name)
🦀 Rust
let name = "Ferris";
name = "小蟹";    // ❌ 编译不过！

看到了吗？这不是 bug，是 Rust 的哲学：「不可变」是默认值。

🤔 为什么默认不许改？

把 Rust 的变量想象成一个盒子：let 就是「装东西进去」，默认还会贴上封条——谁都不许改里面的东西。想改？必须声明的时候就写 let mut（mut = mutable，可变）。

这规矩乍看很烦，其实是保命的：读代码的人（包括三个月后的你）只要看到 let x = … 且没有 mut，就敢拍胸脯说「x 从头到尾没变过」。Python 里你敢这么保证吗？大项目、多线程场景下，这条默认规矩能救命。

修复：加个 mut，撕掉封条

🦀 Rust
fn main() {
    let mut name = "Ferris";   // mut = 允许修改
    name = "小蟹";              // 现在可以改了
    println!("{name}");
}

注意：mut 只在声明时写一次，之后修改不用再写。

📍 Rust 程序从 fn main() 开始执行，就像 Python 脚本从第一行开始跑。教程里的完整例子都会带上它。

彩蛋：遮蔽（Shadowing）——同名的「新盒子」

还有个容易懵的操作：用 let 再声明一个同名变量。这不叫「修改」，叫「新盒子顶掉旧盒子」：

🦀 Rust
fn main() {
    let x = 5;
    let x = x + 1;    // 新盒子顶掉旧盒子（shadowing）
    let x = x * 2;
    println!("{x}");  // 12
}

它和 Python 的覆盖赋值神似，但有个 Python 做不到的玩法：新盒子可以换类型（比如从字符串盒子换成数字盒子）。处理「同一份数据的不同形态」时特别顺手。现在记住有这回事就行。

🎯 本章要点
  • let 创建变量，默认不可变（immutable）
  • let mut 才是可以打开的盒子
  • 想要「新值顶掉旧值」→ 用 let 再声明一次（shadowing）
  • 换来的好处：代码更可预测，多线程更安全
第 2 章 · 徽章待领：🔍 类型侦探

数据类型：Rust 的强制体检

Python 的变量是万能口袋，今天装数字明天装字符串，谁也管不着。Rust 的每个变量出厂就带类型铭牌。好消息：大部分时候编译器自动帮你猜（类型推断），用起来还是顺滑的；坏消息：一旦定下，就是铁律。

类型对照：老熟人都有新名字

你在 Python 写Rust 里叫备注
inti32（默认）/ i64 / u8…i 系列 = 有符号；u 系列 = 只装非负数
floatf64（默认）/ f32f64 = 双精度浮点
boolbool值是小写 true / false
str&str 和 String两种字符串！第 5 章有它的戏份
（没有字符类型）char单引号，'a'、'中'、'🦀' 都算一个

第一条铁律：单引号 ≠ 双引号

Python 里 'hi' 和 "hi" 随便换。Rust 里这俩是不同物种：单引号只能装「一个字符」（char），双引号装「字符串」。

🦀 Rust
let a = 'x';     // ✅ 一个字符，合法
let b = "hi";    // ✅ 字符串，双引号
let c = 'hi';    // ❌ 俩字符塞进单引号？编译器不答应

彩蛋：'🦀' 是合法的！emoji 再大也算一个 Unicode 字符。字符串永远用双引号。

第二条铁律：绝不偷偷帮你转换类型

Python 很「贴心」：1 + 2.5 偷偷帮你算成 3.5。Rust 觉得偷偷摸摸是不对的：整数和浮点是两种类型，不许直接混算。

🦀 Rust
fn main() {
    let a = 1;       // 推断为 i32
    let b = 2.5;     // 推断为 f64
    let c = a + b;    // ❌ 不许 i32 + f64！
}

想变身？必须当面说清楚 as：

🦀 Rust
fn main() {
    let a = 1;              // i32
    let b = 2.5;            // f64
    let c = a as f64 + b;   // 明说：把 a 当 f64 用
    println!("{c}");
}

「麻烦」换来的好处：永远不会出现 Python 里 1 + "1" 到底是 2 还是 "11" 的类型悬疑剧。类型要变，必须明说。

第三条：布尔值全小写

🐍 Python
ok = True       # 首字母大写
if ok:
    print("好嘞")
🦀 Rust
fn main() {
    let ok = true;    // 全小写！
    if ok {
        println!("好嘞");
    }
}

顺手预告：Rust 的 if 条件必须是货真价实的 bool，if 1 { } 这种「非零即真」的偷懒写法直接编译报错（下一章细讲）。

🎯 本章要点
  • 数字默认 i32 / f64，布尔是小写 true / false
  • 单引号 = 一个字符 char；双引号 = 字符串
  • Rust 绝不偷偷转换类型，要转就写 as
  • let x: i32 = 42; 的类型标注是法律，不是 Python 那种建议
第 3 章 · 徽章待领：🛠 函数工头

函数：每个工人都要签合同

写 Python 函数，类型提示是「礼貌」，不写也能跑。写 Rust 函数，类型是「合同」——不签不让你开工，而且编译器全程盯着你履约。

解剖一个 Rust 函数

🐍 Python
def add(a, b):
    return a + b

print(add(1, 2))
🦀 Rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    println!("{}", add(1, 2));
}
  • fn ≈ def
  • a: i32 —— 每个参数必须标类型，没有商量
  • -> i32 —— 返回类型，也是合同的一部分
  • a + b —— 最后一行不带分号，就是返回值（下面马上讲这个魔法）

分号的哲学：最后一行 = 返回值

Rust 有个 Python 没有的设计：代码块最后一行如果不写分号，它的值就是整个块的值。所以函数最后一行直接写 n * 2，不带分号，它就是返回值——连 return 都省了。这是 Rust 最地道的写法。

🦀 Rust
fn double(n: i32) -> i32 {
    n * 2        // 没有分号：这行的值就是返回值
}

fn main() {
    println!("{}", double(21));
}

分号在这里不是可有可无的标点：加上 =「这事到此为止」；不加 =「这行的结果请拿去用」。一个字符，改变含义。

return 什么时候用？

函数末尾的返回：不写 return，直接表达式，最地道。想在中途提前退出：用 return。

🦀 Rust
fn check(score: i32) -> &str {
    if score >= 60 {
        return "及格";   // 提前返回，用 return
    }
    "挂科"               // 最后一行自动就是返回值
}

fn main() {
    println!("{}", check(75));
}

什么都不返回的函数

不写 -> 就是「无返回值」，相当于 Python 里隐式返回 None：

🦀 Rust
fn shout(msg: &str) {
    println!("{msg}!!!");   // 没有 -> ：不返回东西
}

fn main() {
    shout("你好");
}
💡 看到参数里的 &str 了吗？这个 & 是「借用」的意思——第 5 章的主角，先记住写法就行。另外函数命名和 Python 一样用 snake_case，这个你熟。
🎯 本章要点
  • 签名格式：fn 名字(参数: 类型) -> 返回类型
  • 最后一行不带分号 = 返回值，这是地道写法
  • 中途提前退出才用 return
  • 合同写得清楚，调用处一旦传错，编译期当场报警——绝不等运行时
第 4 章 · 徽章待领：🚦 流程指挥官

控制流：if 的括号去哪了

好消息：if / while / for 的逻辑你全都会，只是换了身衣服。坏消息只有一个：条件必须是货真价实的 bool。

if：括号和冒号都退休了

🐍 Python
score = 85
if score >= 90:
    print("优秀!")
elif score >= 60:
    print("及格!")
else:
    print("加油!")
🦀 Rust
fn main() {
    let score = 85;

    if score >= 90 {
        println!("优秀!");
    } else if score >= 60 {
        println!("及格!");
    } else {
        println!("加油!");
    }
}
  • 条件不用写括号（硬要写编译器会唠叨让你删）
  • 没有冒号和缩进块，大括号负责圈地盘
  • elif 变成 else if
  • 条件必须是 bool：if 1 { } 直接报错——「非零即真」在 Rust 不成立

黑科技：if 是表达式，能直接赋值

if 不光能分支，还能「算出一个值」，直接装进变量——相当于 Python 的三岔路口写法 level = "及格" if score >= 60 else "挂科"：

🦀 Rust
fn main() {
    let score = 61;
    let level = if score >= 60 { "及格" } else { "挂科" };
    println!("{level}");
}

注意：两个分支产出的必须是同一类型——毕竟要装进同一个盒子。

三种循环，对号入座

① loop = while True:，无限循环，靠 break 逃生：

🦀 Rust
fn main() {
    let mut count = 0;
    loop {
        count += 1;
        println!("第 {count} 圈");
        if count >= 3 {
            break;
        }
    }
}

② while 和 Python 几乎一模一样（除了没括号没冒号）：

🦀 Rust
fn main() {
    let mut n = 3;
    while n > 0 {
        println!("{n}!");
        n -= 1;
    }
    println!("发射 🚀");
}

③ for 配范围（Range），日常最常用：

🐍 Python
for i in range(5):
    print(f"第 {i} 圈")
🦀 Rust
fn main() {
    for i in 0..5 {
        println!("第 {i} 圈");
    }
}
PythonRust含义
range(5)0..50、1、2、3、4（不含 5）
range(1, 6)1..6 或 1..=51 到 5（..= 表示含尾巴）
range(0, 10, 2)(0..10).step_by(2)带步长要用方法

break / continue 跟 Python 一模一样，无缝迁移。

🎯 本章要点
  • 条件不用括号不用冒号，但必须是 bool
  • if 是表达式，可以直接给变量赋值
  • loop = 无限循环；while = 条件循环；for + 范围 = 最常用
  • 0..5 ≈ range(5)；1..=5 ≈ range(1, 6)
第 5 章 · 徽章待领：👑 所有权觉醒

所有权：Rust 的灵魂（也是你的第一道坎）

来了，Rust 真正的分水岭——所有权（Ownership）。所有从别的语言转来的人都要在这交学费。别慌：概念本身不难，只是要换个脑子。我们用人话讲。

🚲 先用你熟悉的世界开场

Python 的对象像共享单车：谁都能扫码骑走，公司雇了个保洁阿姨（垃圾回收器 GC）定期回收没人骑的车。

Rust 不养阿姨，它立了条规矩：每辆车只能有一个主人，主人一走，车当场回收。就这一条规矩，内存问题从根上没了。

三条铁律（整个 Rust 都盖在这上面）

1️⃣ 每个值都有一个唯一的主人（owner）
2️⃣ 同一时刻，主人只能有一个
3️⃣ 主人离开作用域，值当场回收

铁律 ③ 演示：作用域结束 = 当场回收

🦀 Rust
fn main() {
    {
        let s = String::from("螃蟹");
        println!("{s}");   // 主人在岗：随便用
    }
    // ← 走出大括号：s 的主人下班，内存当场回收
}

没有 free()，没有 GC，清理时机在编译期就排好了——这就是 Rust 又快又稳的底气。

铁律 ② 演示：赋值 = 过户（move）

Python 赋值是给同一个东西再贴一张名字标签。Rust 赋值是把房本过户——所有权归新主人，旧主人当场失效：

🦀 Rust
fn main() {
    let s1 = String::from("hi");
    let s2 = s1;           // ⚠️ 不是复制！所有权从 s1 过户给 s2
    println!("{s1}");       // ❌ s1 已经作废
}

看到了吗？过完户，旧房主连门都进不去。这不是 bug，是合同精神。

👻 Python 佬熟悉的幽灵 bug

🐍 Python
a = [1, 2, 3]
b = a            # 又贴一张标签到同一个列表
b.append(4)
print(a)         # [1, 2, 3, 4] 😱 a 也被改了！
🦀 Rust
let a = vec![1, 2, 3];   // vec! ≈ Python 的 [1, 2, 3]
let b = a;               // 过户！a 当场失效
// println!("{a}");      // ❌ 编译器：a 已经作废
let c = b.clone();       // 想要一份？明说 clone

「改了 b 惊动了 a」——Python 经典大坑，bug 藏得比对象还深。Rust 里这类问题编译期就死了，轮不到运行时害人。

两个救场法宝

想要两份 → .clone()（明说：复制一份新的）：

🦀 Rust
fn main() {
    let a = String::from("螃蟹");
    let b = a.clone();        // 复制一份新的
    println!("{a} 和 {b}");   // 两个主人，各自安好
}

只想借看 → &（明说：借用，用完就还）：

🦀 Rust
fn main() {
    let s = String::from("你好");
    say_hi(&s);         // 借出去看看，所有权还在我这
    println!("{s}");     // ✅ s 照常使用
}

fn say_hi(msg: &String) {
    println!("收到: {msg}");
}

函数参数基本都用「借用」，字符串参数写 &str 就是这个意思——第 3 章那个悬念的答案。只有真正要「接管」时才传值。

好消息：整数这种小家伙不用操心

🦀 Rust
fn main() {
    let x = 10;
    let y = x;             // 整数是 Copy 类型：自动复制一份
    println!("{x} {y}");   // ✅ 两个都能用
}

数字、布尔、字符这些简单类型是 Copy 类型：赋值时自动复制，旧变量照用不误。所有权过户主要管 String、Vec 这些「大件」。

🧠 为什么要立这个规矩？

  • 不需要 GC：清理时机编译期定死，运行时零垃圾、零停顿
  • 不可能有悬垂指针：想用已回收的值？编译器当场拦下
  • 多线程安全：一份数据一个主人，「数据竞争」这种 bug 直接绝种

代价是你现在感到的那点「烦」，回报是：Python 里那些内存泄漏、意外共享、多线程玄学崩溃，在你 Rust 生涯里闻所未闻。

🎯 本章要点
  • 每个值同时只有一个所有者
  • 赋值 = 过户（move），旧变量当场失效
  • 想复制用 .clone()，想借看用 &
  • 整数等简单类型自动 Copy，不受影响
  • 主人离开作用域 → 值自动回收，全程不需要 GC
