## 必须保持的原则
- 每章具体问题推演，不套固定问答；面向零基础。
- 每个新增组件讲清职责、输入输出、工作原理、替代方案、成本、故障、引入证据。
- 单机升级可能合理，不把扩大规格描写成天然错误。
- 图分开表达物理包含、业务请求往返、管理配置、异步任务；明确示例实现与实际代理跳数。
- 数据和容量为教学假设；产品能力依据官方资料，来源和核对日期可追溯。
- Kubernetes 区分 Cluster / Node / Pod / Container、Service 抽象、控制器、实际代理；边车与额外网关均非必需。
- 逐页导航、移动端、打印/博客导出和案例来源均需最终检查。
